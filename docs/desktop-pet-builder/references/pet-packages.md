# Новый персонаж в коллекции Windows-питомцев

Используй установленный проигрыватель, если он уже поддерживает несколько персонажей. Не создавай ещё одну копию приложения и лицензии лишь ради другого набора кадров. Сначала прочитай документацию и импортёр конкретного проекта: формат пакета не является универсальным для всех приложений.

## Договорённость с проигрывателем

Пакет должен описывать имя, размер холста, нейтральный кадр, полный список изображений, клипы с длительностями и семантические роли. Храни подготовленную прозрачность и тень; в финальный пакет не включай chroma-фон. Исходники и отчёт о генерации держи отдельно.

Для растрового формата `pet-1` базовая структура такая:

```json
{
  "version": "pet-1",
  "name": "Имя персонажа",
  "frameSize": [384, 384],
  "alphaPrepared": true,
  "breathAmplitude": 0,
  "neutral": "neutral",
  "frames": ["neutral", "idle-001"],
  "clips": {
    "idle": [
      {"frame": "neutral", "seconds": 0.08},
      {"frame": "idle-001", "seconds": 0.08}
    ]
  },
  "roles": {"lookaround": "idle"}
}
```

Это ZIP с `manifest.json` в корне и PNG по относительным идентификаторам. Все кадры имеют одинаковый размер. Возможность роли и поведение при её отсутствии проверь в целевом приложении. Не называй одну и ту же анимацию разными эмоциями только для заполнения меню. Для ожидания ответа и реакции на успех подготовь подходящие `think` и `dance` либо аналоги, которые реально поддерживает проигрыватель.

Удержание выбирай по устойчивому участку именно этого клипа. В формате коллекции это объект `holds`, например `"think": {"start": 12, "end": 20, "seconds": 3.2}`. Утилита `audit_sprites.py` использует иной формат — массив с `clip`, `startIndex`, `endIndex`. При необходимости создай отдельный проверочный manifest; не передавай один формат за другой.

Не добавляй растяжение жёсткому корпусу и не дорисовывай глаза поверх готового видео. Небольшое живое движение лучше включать в исходный клип. Дополнительную амплитуду дыхания задавай явно только там, где это подходит анатомии.

## Доведение до результата

1. Согласуй общий масштаб и точку опоры для всех клипов. Сохраняй реальный шаг и прыжок; не выравнивай каждый кадр независимо.
2. Проверь светлый/тёмный фон, внутренние просветы, тень, лицо, начальные и конечные фазы.
3. Запусти штатную проверку пакета. Если приложение предоставляет `--verify-pet-package`, используй её: общий аудит PNG не проверяет семантические действия и настоящий рендерер.
4. Импортируй штатным интерфейсом или командой импорта. Добавление не должно автоматически менять активного персонажа или настройки модели, если такой смены не было в запросе.
5. Проверь, что новый персонаж виден в настройках, доступные действия доходят до завершения, ожидание и успех работают, а возврат к прежнему питомцу возможен.
6. Сохрани пакет, короткое превью и результаты QA. Сообщи отдельно: создан, импортирован, выбран и запущен — это разные состояния.

В глобальный навык не записывай имена аккаунтов, пути конкретного пользователя, API-ключи, идентификаторы заданий и расходы конкретного проекта.
