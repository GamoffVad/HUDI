# Чат и интерфейс питомца

Сохраняй выбранный дизайн персонажа. Стиль интерфейса выводи из согласованного макета и палитры, без обязательного голубого цвета или тёмной темы. Для запроса на нестандартный интерфейс используй собственные шаблоны кнопок, полей, переключателей, списков и контекстного меню; системный выбор файла допустим.

Если согласован матовый стеклянный материал, непрозрачная заливка или просто градиент не заменяют размытие фона. В Windows 11 22H2+ для WPF-панелей можно использовать DWM Desktop Acrylic (`DWMWA_SYSTEMBACKDROP_TYPE=38`, `DWMSBT_TRANSIENTWINDOW=3`), прозрачный CompositionTarget и `DwmExtendFrameIntoClientArea`. Такие панели не должны быть layered-окнами `AllowsTransparency=true`; сам растровый питомец остаётся отдельным прозрачным окном. Проверяй скруглённую область/хвост пузыря, прозрачные поля и светлую кромку. На неподдерживаемой ОС оставь читаемый резервный материал и сообщи ограничение. Снимок RenderTargetBitmap содержит только WPF-слой, а не системное размытие: стекло проверяй в настоящем окне поверх фона.

Не совмещай системное стекло с `SetWindowRgn`: регион может обрезать только содержимое, оставить прямоугольное размытие снаружи и отключить нативное скругление. Для DWM-панели используй системное скругление (`DWMWA_WINDOW_CORNER_PREFERENCE`) и согласуй с ним радиус рамки и заливки WPF (стандартный большой радиус Windows — 8 DIP). Произвольный радиус или хвост пузыря требуют отдельного решения для отсечения самого материала; одной маски WPF недостаточно. Не выдавай успешную сборку или значение атрибута DWM за визуальную проверку: осмотри все четыре угла настоящего окна, в том числе после изменения размера. При остановленной проверке явно оставь её незавершённой.

Различай матовое размытие и прозрачность, через которую различим рабочий стол. Если пользователь просит видеть приложения под окном и регулировать прозрачность фона, одна альфа-заливка поверх Acrylic недостаточна. Для WPF можно использовать отдельный режим `WindowStyle=None`, `AllowsTransparency=true`, прозрачный фон окна и отсутствие DWM-бэкдропа. Меняй альфа-канал фоновой поверхности, а не `Window.Opacity`, чтобы текст и кнопки оставались чёткими. В таком режиме скругляй сам альфа-слой. Проверяй нативный layered-флаг, альфа-пиксели и отсутствие непрозрачной подложки, а затем настоящее окно поверх различимого тестового фона. Не называй проверку прозрачной кисти доказательством прозрачности на рабочем столе.

## Взаимодействие

При переносе утверждённого макета сравнивай и материал, и структуру: размер окна, сетку подписей и полей, высоты элементов, заголовок, отступы, положение действий. Нельзя заменять компактную форму длинной вертикальной анкетой со скроллом без необходимости. Редкие параметры можно вынести в явный раскрывающийся раздел, сохранив значения и проверки. Покажи снимок фактической разметки после сборки; не выдавай исходный сгенерированный макет за готовый интерфейс. Отдельно проверь ввод и синхронизацию ключа, смену провайдера, защиту origin, сохранение скрытых параметров.

У всплывающих WPF-панелей состояние закрытия устанавливай в `OnClosing` до нативной деактивации, а не только в `Closed`. Закрытие из `Deactivated` откладывай через Dispatcher и повторно проверяй состояние/видимость: повторный `Close()` из `WM_ACTIVATE` во время первого закрытия может завершить весь процесс. При отменённом закрытии восстанови состояние. Проверяй не только статический рендер формы, но и цепочки «меню → выбор питомца», «меню → чат», закрытие крестиком и потерю фокуса. Если локальный журнал пуст, проверь свежий .NET Runtime/Application Error в журнале Windows.

- Двойной клик открывает вопрос над питомцем, одиночный показывает последний ответ. Разделяй их системным интервалом двойного клика: одиночное действие не срабатывает перед двойным. Перетаскивание отменяет ожидающий клик.
- Окно следует за питомцем и остаётся в рабочей области текущего монитора с учётом DPI. При нехватке места сверху размещай рядом.
- Для минимального чата используй одну строку с кнопкой отправки внутри общего контура. Высота растёт при переносе текста и уменьшается при удалении; после разумного предела включается прокрутка. Не добавляй заголовок, нижние действия и подсказки отдельными строками, если пользователь просит только поле. Сохраняй черновик при повторном открытии. Для WPF обрабатывай Enter в PreviewKeyDown, чтобы TextBox не поглотил событие как перенос; проверяй также Shift+Enter.
- Размер удобно менять ползунком с немедленным результатом и числовой подсказкой. При изменении размера сохраняй центр и положение стоп; во время перетаскивания шкалы закрепляй панель, чтобы она не смещалась из-под курсора вслед за питомцем. Проверяй границы экрана и сохранение размера после перезапуска.
- Enter отправляет, Shift+Enter добавляет строку. Ответ можно выделить и скопировать; длинный текст прокручивается. Клавиатурный фокус и Escape должны работать.
- Закрытие пузыря само по себе не обязано отменять запрос. Отмена — явное действие. Не отправляй одинаковый запрос повторно из-за двойного нажатия.
- Если запрошен автоматический показ ответа, открывай его сразу после завершения запроса без перехвата клавиатурного фокуса. Для режима «только точки» ожидание рисуй в отдельном прозрачном окне без стеклянной подложки: прозрачная кисть внутри окна с DWM Acrylic всё равно оставит карточку. Сохраняй зазор между диалогом и питомцем; явную отмену запроса можно оставить в меню.

## Локальные заметки

Добавляй блокнот только по запросу. Дай создавать, открывать, редактировать и удалять заметки; сохраняй текст автоматически и сбрасывай ожидающее сохранение при закрытии окна или приложения. Ошибка записи не должна выдавать статус «Сохранено» или уничтожать текст. Используй атомарную замену файла, резервную копию, проверку формата и возможность отменить удаление. Явно определи, общие ли заметки для коллекции или отдельные для каждого персонажа. Не отправляй их модели автоматически без запроса пользователя. Проверь перезапуск, быстрый выход сразу после ввода, кириллицу, восстановление резервной копии и отказ от перезаписи неизвестного формата.

## Связь с движением

Задай в спецификации семантические роли `thinking`, `success`, `error`, `idle`, а затем сопоставь их подходящим клипам конкретного персонажа. Танец, задумчивый жест или движение хвоста — варианты, а не фиксированная анатомия.

Один контроллер запроса ведёт состояния idle/thinking/answered/error/canceled. При ожидании запроси безопасный выход из текущего жеста и удерживай цельную анимацию размышления. При успехе отпусти удержание через его границу и поставь анимацию радости в очередь. Ошибка и отмена не вызывают празднование. Быстрый ответ должен убрать ещё не начавшееся ожидание. Закрытие приложения отменяет сетевой запрос и игнорирует запоздавшие callbacks.

Не рисуй новые глаза поверх кадров ради состояния чата. Не прерывай произвольную позу наведением и не включай взгляд за курсором, если пользователь отказался от него. Обновление текста ответа не должно перезапускать движение.

## Подключение и секреты

Настройки: провайдер, базовый URL, формат API, точное имя модели, ключ, системная инструкция, потоковый ответ, история, лимит токенов, тайм-аут. Дополнительные параметры отправляй только когда они включены и поддерживаются моделью; температура не универсальна. Список моделей загружай с сервера, разрешай ручное имя. Не закрепляй «последнюю» модель в глобальном навыке.

Если нужны готовые провайдеры, храни проверенные профили адреса, API, модели, лимита, тайм-аута и допустимых параметров. Проверяй актуальность по официальной документации и фиксируй дату/источники в проекте. При явном выборе профиля подставляй значения, очищай ключ другого сервера и сохраняй личную системную инструкцию; при открытии настроек не сбрасывай уже сохранённые поля. Для локального сервера выбирай реально установленную модель, не выдумывай её имя. Поздний результат загрузки моделей предыдущего провайдера не должен менять новый профиль. Проверь заголовки авторизации и разные формы списка моделей на тестовом HTTP-обработчике; перечисление провайдера в меню само по себе не доказывает совместимость.

Если пользователь выбрал ввод своего ключа в приложении, реализуй именно этот путь. Не создавай аккаунт или ключ без отдельного запроса. Ключ маскируется в UI, сохраняется средствами ОС (например, Windows DPAPI на пользователя), не попадает в журнал/исходники/спецификацию. Свяжи сохранённый ключ с origin сервера и требуй новый ввод при смене origin. HTTPS обязателен для удалённого API; HTTP допустим для loopback. Не пересылай авторизацию через редиректы. Локальная модель может работать без ключа.

Различай лицензионный код питомца и ключ модели. В продаваемый exe не встраивай общий ключ разработчика. При централизованной оплате нужен отдельный сервер с контролем доступа и лимитов.

## Проверка

Проверь оба типа ответа, потоковую кириллицу, завершение SSE, пустой ответ, 401/429, разрыв соединения, тайм-аут, отмену, повторный запуск и закрытие окна. Тестовый сервер или HttpMessageHandler должен проверять фактический запрос. Не выдавай тестовый ответ за работу настоящего провайдера. Проверь шифрование сохранённого ключа и блокировку его переноса на другой origin. Проверь состояния движения, включая долгий и мгновенный ответ. Реальные запросы выполняй только с авторизованным ключом.
