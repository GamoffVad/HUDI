# Питомцы рабочего стола

Создай работающего питомца Windows или исправь существующего, сохранив личность персонажа и требования пользователя. Навык подходит для людей, животных, роботов, фантастических существ, предметов, 2D и 3D-стилизации. Анатомия, одежда, палитра, лицо и набор действий задаются отдельно для каждого проекта.

## Сначала определи границы работы

- Для существующего питомца найди исходники, ресурсы, текущий исполняемый файл и настройки. Исправляй конкретную причину проблемы; сохраняй рабочую сборку для отката.
- Для нового питомца создай отдельный проект и уникальный идентификатор. Не заменяй другого работающего питомца, если это не входит в запрос.
- Если нужны только референс, позы или анимации, остановись на этих материалах. Не устанавливай приложение без соответствующего запроса.
- Для облачного питомца ChatGPT используй доступный навык/плагин этого продукта. Для локальной адаптации существующего персонажа в Codex прочитай [codex-companion.md](references/codex-companion.md); не путай облачную коллекцию и локальный выбор.

## Зафиксируй персонажа и поведение

Создай в проекте `pet-spec.json`, используя [шаблон](assets/pet-spec.template.json) как основу. Выведи известные параметры из референса и переписки; спрашивай только то, без чего нельзя продолжить. Не требуй повторного подтверждения уже выбранной внешности.

Укажи:

- референсы и признаки, которые нельзя менять: силуэт, пропорции, материалы, цвета, конечности, аксессуары;
- правила лица: обычная мимика, только глаза, без лица или другой вариант из задания;
- действия с учётом анатомии, нейтральные позы, направления, удержания и способы выхода из них;
- нужные реакции на клик, наведение и события Windows, а также приоритеты и прерываемость;
- размер питомца на экране, ограничения по ресурсам и известный бюджет генерации.

Не переноси индивидуальные решения другого питомца: два голубых глаза, запрет рта, капюшон, карманы, боевая стойка, отражение по горизонтали или отключённое наведение не являются универсальными требованиями. Например, для четвероногого персонажа замени жесты рук подходящими движениями лап, головы и хвоста.

## Выбери маршрут по имеющимся материалам

**Нужна генерация или замена плохого движения:** прочитай [generation.md](references/generation.md), включая требования чистой подложки, пробного вырезания и отдельные шаблоны базового кадра и движения. Используй выбранный пользователем сервис; Higgsfield подключай через доступные инструменты. Не расходуй кредиты ради проверки самого навыка. Если готовые материалы уже подходят, используй их. Правка промпта сама по себе не разрешает генерацию; соблюдай явный запрет пользователя на запуск видео.

**Нужны прозрачные кадры, чёткий контур, тень или плавные стыки:** прочитай [assets-and-motion.md](references/assets-and-motion.md), включая проверку фактического размера и DPI. Сначала исследуй исходник, маску и масштабирование в проигрывателе; сохраняй разрешение мастер-кадров и избегай уменьшения с последующим растягиванием. Долгое смешивание двух сильно разных поз не заменяет переходного движения.

**Нужна интеграция, поведение или готовое приложение:** прочитай [windows-runtime.md](references/windows-runtime.md). Сохраняй подходящий существующий стек; для нового Windows-приложения допустим прозрачный WPF-проигрыватель или иной подходящий движок. Не превращай растр в отдельные части лица без технического основания.

**Нужен новый персонаж для существующей коллекции:** прочитай [pet-packages.md](references/pet-packages.md), затем локальное описание формата приложения. Подготовь отдельный пакет с собственными ролями, размерами и удержаниями; импортируй его через штатную проверку, сохранив текущий выбор, если пользователь не просил переключиться.

**Нужен чат, меню или настройки модели:** прочитай [chat-integration.md](references/chat-integration.md). Для нового полного приложения по умолчанию предложи двойной клик для вопроса, одиночный для ответа и семантические реакции ожидания/успеха; явные требования проекта имеют приоритет. Если запрошены только изображения, анимации или исправление движения, не добавляй чат автоматически.

**Нужны установщик, продажа или генератор активаций:** прочитай [distribution-and-licensing.md](references/distribution-and-licensing.md). Установщик покупателя и инструмент издателя — разные артефакты. Внешность, идентификатор продукта и пара ключей уникальны для проекта.

## Порядок доведения до результата

**Персонаж должен целиком оставаться в кадре на протяжении всей анимации. Обрезание любой части тела недопустимо.** Это относится к исходному ролику, раскадровке и отображению в приложении: голова, головной убор, конечности, обувь, хвост, крылья и удерживаемые предметы должны помещаться с запасом для движения. Передавай это требование явно в каждый запрос генерации и проверяй весь результат по правилам [generation.md](references/generation.md#персонаж-целиком-в-кадре). Ролик с обрезанием не считать готовым к подключению.

1. Проверь одну репрезентативную анимацию в реальном размере питомца: внешность, полный силуэт, лицо, фон, тень и начало/конец. Для уже проверенных ресурсов не начинай генерацию заново.
2. Подготовь остальные действия и явные связи `вход → действие/удержание → выход`. При смене положения используй настоящие промежуточные движения либо существующий риг. Для нейтрального цикла и точных жестов примени правила [живого движения и циклов](references/generation.md#живое-движение-и-проверяемая-эмоция); проверяй фактические контакты, лицо и кисти, а не только выполнение промпта.
3. Сохраняй исходные ролики, параметры, идентификаторы заданий, результаты и расход кредитов в проекте. Ничего из этого, включая личные пути и данные аккаунта, не записывай в глобальный навык.
4. Подготовь manifest и прозрачные ресурсы. Проверь их скриптом ниже и визуально на светлом и тёмном фоне.
5. Интегрируй поведение, проверь стыки, удержания и реакции в настоящем проигрывателе. Обычное завершение действия не должно мгновенно заменяться общей нейтральной картинкой.
6. Собери отдельную версию, проверь запуск и только затем замени нужный экземпляр питомца, если установка/обновление входит в запрос. Сохрани его размер и положение.

## Проверка ресурсов

Утилита требует Python и Pillow. Она не генерирует и не изменяет исходные кадры. Формат manifest описан в [assets-and-motion.md](references/assets-and-motion.md).

```powershell
python "<skill-dir>/scripts/audit_sprites.py" "<project>/assets/manifest.json" --frames-dir "<project>/assets/frames" --report "<project>/qa/sprites.json" --sheet "<project>/qa/poses.jpg"
```

Скрипт проверяет ссылки, размеры, длительности, границы удержаний, прозрачность и указанные стыки. Контактный лист помогает осмотреть начало, середину и конец действий. Он не доказывает отсутствие рта, правильность анатомии или плавность всего видео — это проверь отдельно, включая проблемные участки.

Проверяй существенные свойства: отсутствие обрезанных конечностей, ореолов и дырок; сохранение полупрозрачной тени; совпадение лица с договорённостью; завершение длинного удержания; отсутствие скачка на стыках; корректные прерывания; настройки и производительность. Не обещай универсальную поддержку курсорного взгляда для любой растровой анимации без проверки её устройства.

В результате сообщи, что создано или исправлено, где находится сборка/превью, запущен ли питомец, какие проверки прошли и сколько кредитов фактически потрачено. Отделяй завершённую работу от ограничений или ещё выполняющихся генераций.
